01

What we propose

One record, owned by the patient, built as a focused Phase 1.

Records live in silos. Solo practices get left out. A patient sees seven providers and ends up with seven portals — a login for each clinic, each holding a slice of the story and none holding the whole. When they meet a new provider, they re-key the same name, the same date of birth, the same history, and hope the labs from one place make it to the next. The record follows the clinic, not the person.

CareManager flips that. People build and own one health record that travels with them — and independent, alternative-care providers can attach to it. This proposal is scoped to Phase 1: the patient experience on mobile and web, and the platform behind it, ready to put in front of real providers. Phase 2 — the engagement layer and admin monetization tools — is outlined at a glance in section 13, to be scoped in full once Phase 1 is underway.

What we build

The patient experience on mobile and web, the super admin platform behind it, and the security and infrastructure foundation underneath.

How we work

Two-week milestones, each a demonstrable release you sign off before the next begins. No guesses committed as fact.

What you own

Full code ownership and IP assignment on delivery, in your own cloud accounts.

How the pieces connect

A patient's record, and how each role reaches it.

A patient signs up once and builds a record that lives entirely inside CareManager, not inside any single clinic's system. They can add family members or invited caregivers with their own access, and share select parts of their record with a provider, one visit at a time. The Super Admin platform sits above this as the operational layer — provisioning accounts, watching platform health, and managing the configuration every patient-facing screen reads from.

This first build does not yet include a dedicated workspace for providers themselves — the record is structured to make that a clean next step, not a rebuild.

Security, compliance and ownership

Built HIPAA-ready from the first environment; certification is a process you own, and we help you run it.

What CareManager protects

  • Encryption in transit and at rest
  • Malware-scanned document uploads (Yara + ClamAV)
  • Multi-tenant identity isolation via Keycloak
  • Audit logging across the platform

What you own

  • Full code ownership, IP assigned on delivery
  • Infrastructure in your own cloud account
  • A patient's data belongs to their record — not to any single clinic
HIPAA-ready vs. HIPAA-certified

We build CareManager's platform and architecture to be HIPAA-ready — encryption, access controls, audit logging, and the infrastructure patterns HIPAA expects, in place from the first environment. Formal HIPAA certification is a compliance process CareManager itself has to complete, typically by subscribing to a compliance-automation service such as Sprinto or similar, alongside a third-party audit. Mindbowser is not the certifying party, but we help: preparing the technical evidence, closing any gaps a compliance review surfaces, and supporting the audit itself.

Mindbowser separately holds its own SOC 2 Type II certification as a company (see About Mindbowser) — that is Mindbowser's own credential, distinct from CareManager's own compliance certification, which remains yours to obtain.

DevOps and environments

The infrastructure and environments Phase 1 stands up.

The delivery pipeline and security gates that run on every change are covered in section 11; this section is the infrastructure they run on.

Infrastructure as code

OpenTofu + Terragrunt across Dev, QA, Stage, and a HIPAA-ready single-AZ production environment.

Delivery pipelines

CI/CD for the web app, the backend, and mobile app builds and store publishing (Android and iOS).

Security gates

File-scanning on every upload (Yara + ClamAV), cloud posture scanning (Prowler), and a pentesting pass before go-live.

Multi-tenant identity

Keycloak configured with organization support, so multi-tenancy is foundational, not retrofitted.

DevOps splits across both phases

Phase 1 stands up the full HIPAA-ready foundation above: a single-AZ production environment, CI/CD, multi-tenant identity, and the security gates. Multi-AZ resilience and disaster-recovery setup are Phase 2 scope — see section 13 — once real usage patterns inform how the platform should scale.
